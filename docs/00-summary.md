# Rokid AI Glass 길 찾기 조사 요약

작성: 2026-11-04. 세부 근거는 같은 폴더의 `01~03`, `evidence-*.md` 에 있다.
판정 표기: 확인 / 부분확인 / 반증 / 미확인. **직접 실행해 본 것은 카카오 도보 API 호출 한 건뿐**이고, 나머지는 문서·소스 읽기다.

## 목표
폰에서 목적지를 입력하면 안경에 도보 안내를 띄운다. 안드로이드 컴패니언 앱 없이, Slack을 입력 창구로 쓴다 (사용자 폰은 iPhone).

## 구조 (제안)
```
폰 Slack: /route 강남역 ─> Slack(Socket Mode) ─> 서버 ─> 카카오 도보 API
                                                  │
                                                  └─ WebSocket ─> 안경 앱 (한 줄 표시, 터치로 다음 단계)
```
- Slack은 명령·요약 전달용이다. 위치 스트림이나 경로 계산은 하지 않는다.
- 서버가 지오코딩, 경로 계산, 진행 상태를 맡는다.
- 안경은 표시와 "다음" 입력만 한다.

## 앞서 틀렸던 것 (정정)
- "카카오는 자동차만" → **틀림.** 카카오맵 REST에 도보 API가 있다 (자동차 전용은 카카오모빌리티 내비 API).
- "OwnTracks Move는 촘촘히 보냄" → **틀림.** iOS 기본은 100m 또는 300초 중 먼저 오는 쪽. 수 초 간격을 보장하지 않음.
- "OSRM 공개 서버로 도보 가능" → **foot 프로파일 요청해도 자동차 경로**가 나옴. `routing.openstreetmap.de/routed-foot` 는 보행 경로.
- "안경에 GPS 없음" → **미확인.** 스펙표에 없고 일본어 가이드에 "GPS does not work"라는 서술이 있을 뿐. 자기계도 미확인.
- "관리자는 비공개 채널을 볼 수 있다" → 플랜에 따라 다름. Free/Pro 의 Owner는 일반 내보내기로 못 받음.

## 카카오 도보 API 실측 (유일한 직접 실행)
- 응답: `route.legs[].steps[]` 에 `guidance`, `distance`, `time`, 시작 `x/y`, `path.points`.
- 단계 경계의 좌표는 끊김 없이 이어진다.
- **문구에 좌/우회전이 없다.** 예: `국기원입구교차로에서 548m 이동`, `삼정빌딩까지 횡단보도 이용`. 랜드마크와 거리 중심.
- 좌표로 회전 방향을 계산해 봤으나, 횡단보도 단계에서 -43°~+48° 로 흔들려 화살표용으로는 신뢰도가 낮다 (경로 1건만 본 결과).
- 결론: 화살표 대신 텍스트(`교차로명까지 548m`)로 가거나, TMAP `turnType` 과 비교 필요.

### 추가 실측 (2026-11-04, 서버 작업 중 직접 실행)
- 도보 API 파라미터는 `start_x`, `start_y`, `end_x`, `end_y` (경도=x, 위도=y). `origin`/`destination` 은 400 ValidationError.
- 지오코딩은 `GET /v2/local/search/keyword.json?query=` 로 동작. 없는 장소는 `documents: []`.
- 응답 최상위 `route.properties` 에 `totalDistance`, `totalTime`, `landingUrl`(카카오맵 링크).
- 서울역→남대문시장(972m, 13단계)에서 `왼쪽길로 19m 이동` 문구가 나왔다. **좌/우 문구가 아예 없는 건 아니다.** 다만 빈도는 낮다.
- 6m·18m 같은 짧은 횡단보도 단계가 많다. 안경에서 탭으로 넘기기엔 잘게 쪼개져 있어 병합 여부를 실기에서 판단할 것.

## 열린 문제
1. 안경 기기 보유 여부와 앱 설치 경로(개발 케이블 얼리액세스 또는 CXR-M).
2. 이동 중 네트워크: iPhone 개인용 핫스팟은 연결 기기가 없으면 잠들어 안경이 붙지 못함. 설정 화면을 켜 둬야 한다고 `Rokid_Claude` 문서에 있음.
3. 한국 정식 출시국 아님 (구매·계정 등록 문제 가능).
4. 단색 녹색 화면, 해상도 출처마다 상이 (480x640 / 640x480 / 480x400 …). 실기 확인 필요.
5. 한국어 음성 인식 품질 미확인.
6. 실시간 안내(위치 갱신)는 iOS 에서 어려움. OwnTracks 간격을 줄일 수 있는지 실측 필요.
7. TMAP 비교, 카카오 도보 약관(상업/개인) 미확인.

## 선례: `Rokid_Claude` (소스 확인)
안경 앱이 폰 없이 Mac 릴레이에 WebSocket 으로 붙는 구조. 안경 앱 약 1,400줄, OkHttp 4.12.0, minSdk 31. `RelayClient.kt` 76줄이 연결·재연결·JSON 송수신 전부. 서버 주소·토큰은 `RCLAUDE:url=..;token=..` QR 로 설정. 외출 시에는 폰 핫스팟 + ngrok.
이 구조에서 "Claude Code 릴레이"를 "경로 안내 서버"로 바꾸면 우리 구조가 된다. (한계: 코드와 문서 분석이며 안경에서 실행해 보지 않음.)
