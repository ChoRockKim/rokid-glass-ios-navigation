# glasses-android (Rokid 안경용 APK)

Kotlin 안드로이드 앱. 서버(`server/`)의 WebSocket `/glass?map=1` 에 붙어 안내 문구와 미니맵을 그린다. `/viewer`(웹)와 같은 화면을 안경에서 직접 띄우는 것.

선택 근거: 공개된 Rokid 안경 앱 10개 중 8개가 Kotlin (Rokid 공식 `glass3_sdk_demo`, 지도 HUD `Anezium/Rokid-GMaps` 포함). 구성(minSdk 28, compileSdk 34, Kotlin 2.1, View+Canvas)은 Rokid-GMaps 를 따랐다. 통신은 OkHttp 4.12 (`Rokid_Claude` 와 같은 버전).

## 화면
- 480×282 dp 를 화면 아래 가운데에 그린다. 나머지는 검정(투과형 안경에서 안 보임).
- 위: `3/14`, `→ 목적지` / 가운데: 안내 두 줄 / 배경: 미니맵(경로·주변 도로·다음 회전 ◆·나 ▲)
- 처음 실행하면 **연결 코드 4자리**가 뜬다 (페어링).

## 연결 방식
**기본: 안경 전용 토큰을 APK 에 넣어 빌드** → 설치하고 켜면 바로 연결.
- 서버 Railway 변수 `GLASS_DEVICE_TOKEN` 과 같은 값을 빌드 때 `-PDEVICE_TOKEN=…` 으로 준다. 저장소에는 넣지 않는다.
- **APK 안에 토큰이 들어 있으므로 APK 를 남에게 주지 말 것.** 새면 Railway 에서 `GLASS_DEVICE_TOKEN` 만 바꾸고 APK 를 다시 빌드.
- 서버가 이 토큰을 거절(401)하면 아래 페어링으로 넘어간다.

### 예비: 페어링
1. 안경 앱을 켜면 `연결 코드 1234` 가 뜬다 (서버 `POST /pair/request`).
2. 폰 단축어 **"안경 연결"** 로 그 코드를 보낸다 (`POST /pair/approve`, `API_TOKEN` 인증). 만드는 법은 `docs/ios-shortcuts.md`.
3. 안경이 2초마다 확인하다가 승인되면 토큰을 받아 저장하고 연결한다. 다음부터는 바로 연결.
   서버 `GLASS_TOKEN` 을 바꾸면 401 → 자동으로 다시 페어링.

## 입력 (실기 미확인)
| 입력 | 길안내 화면 | 메뉴 |
|---|---|---|
| ENTER, DPAD_CENTER, 미디어 재생/일시정지 (탭) | 화면 모양 바꾸기 (전체 지도 ↔ 간소) | 선택 |
| DPAD_RIGHT/DOWN, 미디어 다음 | 다음 단계 미리보기 | 아래로 |
| DPAD_LEFT/UP, 미디어 이전 | 이전 단계 미리보기 | 위로 |
| BACK, ESC (더블탭) | 메뉴 열기 | 앱 종료 (목적지 선택 중이면 선택 취소) |

`Rokid_Claude` 주석 기준 탭=ENTER, 쓸기=DPAD_LEFT/RIGHT. 어느 쓸기 방향이 앞인지는 실기에서 확인.

### R08 링 (R08 Access Bridge)
소스(Anezium/R08-Access-Bridge)만 읽고 맞춘 것. 실기 미확인.
- 링 앞/뒤 → 접근성 포커스 노드에 `ACTION_SCROLL_FORWARD/BACKWARD` → 다음/이전 (HudView 가 포커스·스크롤 가능 노드로 보인다)
- 링 탭 → `ACTION_CLICK` → 선택, 더블탭 → 뒤로(`GLOBAL_ACTION_BACK`) → 메뉴 (메뉴에서 한 번 더 = 앱 종료)
- 스와이프 제스처로 떨어질 때는 세로 플링을 다음/이전으로, Stable 모드(미디어 키)는 위 표대로.

## 자동 업데이트 · Wi-Fi 자동 켜기 (0.3.21, rokid-conversate 와 같은 방식)
**자동 업데이트**: 서버에 연결되면(그 뒤 6시간마다) 새 버전을 확인하고, 있으면 PackageInstaller 세션 + `USER_ACTION_NOT_REQUIRED` 로 **확인 창 없이** 설치한 뒤 앱이 다시 켜진다 (`Updater`, `UpdateReceiver`).
- **앱을 켜면** 서버에 처음 연결될 때 1회 확인하고, 새 버전이 있으면 안내 중이거나 메뉴가 열려 있어도 바로 설치 (0.3.23. 경로는 서버에 저장돼 재시작 후 이어짐). 그 뒤 6시간마다 확인한 새 버전은 길안내 중·메뉴 열림이면 미루고 안내가 끝나면(경로 없음·도착) 설치.
- 조건 (rokid-conversate 실기 기준): Android 12+, '이 출처 허용' 켜짐, 이 앱이 설치자로 기록됨. 처음 한 번은 확인 창이 뜰 수 있다 (시스템이 확인을 요구하면 그 창을 띄움). 그 뒤로는 이 앱이 직접 설치했으므로 설치자로 기록된다 (미확인).
- '이 출처 허용'이 꺼져 있으면 자동으로는 설정 화면을 띄우지 않는다 (앱을 켤 때 새 버전이 있으면 안내 문구만). 메뉴 > 설정 > 업데이트에서 직접.

**Wi-Fi 자동 켜기** (`WifiEnabler`): 안경은 배터리 때문에 Wi-Fi 를 꺼 두는데, 꺼져 있으면 10초마다 켜 본다. 왼쪽 아래에 `Wi-Fi 켜는 중…` / `Wi-Fi 연결 기다리는 중 · 핫스팟을 켜 두세요` / `Wi-Fi 못 켬 · 이유 · 탭하면 설정`. 켜지면 서버에 바로 다시 연결.
- 꺼져 있어 켜는 중이거나 연결을 기다리는 동안은 화면 가운데에 작은 모달(`Wi-Fi 켜는 중` / `Wi-Fi 연결 중` / `Wi-Fi 를 켜지 못했습니다`)이 뜨고, 연결되면 사라진다. 못 켰을 때 탭하면 Wi-Fi 설정 (0.3.22).
- 안드로이드는 targetSdk 28 이하 앱에만 Wi-Fi 켜기를 허용하고, 본앱은 확인 없는 OTA 때문에 28로 낮출 수 없다 → **"길안내 Wi-Fi 도우미"** (`wifihelper` 모듈, targetSdk 28, 화면 없음)를 한 번 따로 설치한다. rokid-conversate 의 도우미가 이미 깔려 있으면 그것도 쓴다.
- 그 밖에 `Settings.Global.WIFI_ON`(adb 로 WRITE_SECURE_SETTINGS 를 준 경우), `setWifiEnabled`, 숨은 API 도 차례로 시도.
- 네트워크(핫스팟) 고르기는 시스템에 맡긴다 (저장된 iPhone 핫스팟에 자동 연결).
- 릴리스 빌드: `scripts/release.sh` 가 `build/rokid-route-wifihelper.apk` 도 만든다.

## 메뉴 · OTA 업데이트
뒤로 가기 → 메뉴 (0.3.23 부터 안내 중일 때 "경로 다시 찾기" 가 맨 위 바로 아래, "안내 종료" 도 메인에):
| 메인 | 안의 항목 |
|---|---|
| 길안내 화면으로 (안내 없으면 "화면 닫기") | 메뉴 닫기. 메뉴에서 뒤로 = 앱 종료 |
| 말해서 찾기 | 안경 마이크로 목적지를 말함 (말이 끝나고 0.9초 조용하면 끝, 탭 = 바로 끝, 뒤로 = 취소) → 서버가 CLOVA Speech 로 글자로 바꿈 (즐겨찾기·최근 이름을 힌트로) → `들은 말: "…"` 제목으로 ★즐겨찾기·최근 중 닮은 것 + 카카오 검색 후보를 띄움 → 고르면 즐겨찾기와 같은 규칙(800m 안 도보, 멀면 대중교통). 잘못 알아들었으면 뒤로 = 취소하고 다시. 처음 한 번 마이크 권한 허용 (0.3.24, 실기 미확인) |
| 목적지 ▸ | **최근 (n)** (길안내를 시작한 목적지 최근 8곳, 서버 `/data/recent.json`) / 즐겨찾기 카테고리들 → 장소(마지막 위치에서 직선거리) → 바로 안내: 직선 800m 안이면 도보, 멀면 대중교통 후보 카드에서 고름. 즐겨찾기 등록은 폰 `/places` 또는 단축어 |
| 버스·지하철 시간 | 가장 가까운 버스 정류장(300m)·지하철역(800m) 모든 노선, 20초마다 갱신, 탭 = 새로고침 |
| 경로 다시 찾기 (안내 중) | "길안내 화면으로" 바로 아래. 지금 위치에서 같은 목적지로 다시 찾음 |
| 안내 종료 (안내 중) | 두 번 선택 |
| 설정 ▸ (새 버전이 있으면 `●`) | 지도: 자동/항상/끄기 / 방향 다시 맞추기 / 업데이트 확인·설치 |
| 앱 종료 | |

**하차 알림 (소리 없음)**: 탑승 중 하차까지 1정거장 남거나 600m 안 → `[버스] 다음 정류장에서 하차` + 초록 테두리, 150m 안 → `이번 정류장에서 하차` + 흰 테두리·흰 글씨. 처음 8초는 테두리가 깜빡이고 그다음은 얇게 켜 둔다 (서버 step `ride.alightAlert`). 정류장 좌표가 없어 정거장 수는 거리 비율로 추정.

폰에서 시작한 목적지에 후보가 여럿이면(예: 맥도날드 지점들) 서버가 `{type:"choose"}` 로 목록을 보내고, 같은 메뉴 모양으로 띄운다. 대중교통이면 이어서 경로 후보도 같은 방식. 쓸기 이동 · 탭 선택(`{type:"chosen", id, index}`) · 뒤로 취소(index -1). 60초 안에 안 고르면 맨 위 항목. 폰 단축어는 "안경에서 고르세요"로 바로 끝나고, 결과는 왼쪽 아래 알림(`{type:"notice"}`) (`docs/ios-shortcuts.md` 목적지 고르기).

앱 아이콘: `res/drawable/ic_launcher_*.xml` (적응형 벡터, 배경 완전 투명, 접힌 지도 + 경로 + 핀, 테마 아이콘용 한 색 버전 포함).

**화면 모양** (탭으로 바꿈, 안경에 저장): 전체 지도 / 간소 = 왼쪽 150x150 에 주변 도로를 가는 선으로만 + 경로·나 (1m = 0.6, 앞쪽 약 200m), 안내 글자는 오른쪽 아래에 작게.

**버스·지하철 정류장 점 (0.3.25)**: 서버가 경로를 시작할 때 카카오 키워드 검색으로 구간의 정류장·역 위치를 찾아(버스정류장 분류·지하철역 SW8, 경로선 120m 안만) 지도에 작은 점으로 찍는다. 타고 있으면 지난 정류장은 흐리게, 다음에 설 정류장 옆에 이름, 내릴 정류장은 `이름 (하차)`. 둘째 줄은 `다음 마장축산물시장 · 성동구청 하차 · 3정거장` (남은 정거장 = 아직 안 지난 정류장 수, 하차 알림도 이 수로). 못 찾은 정류장은 점 없이 건너뜀 (서버 로그 `stops 421: 5/5 찾음`). 실제 카카오 분류 이름·찾는 비율은 실서버 로그로 확인 필요.

오른쪽 아래 상태 줄: `[새 버전] 14:00 Wi-Fi ● ▭82%` (현재 시각 포함).

**정류장 보드** (간소 화면 + 대중교통): 탈 정류장·역에서 100m 안이고 아직 안 탔으면, 오른쪽 가운데에 그 정류장 실시간 도착을 세로 목록으로 — 내가 탈 노선은 굵고 밝게("273번 3분 · 10분"), 나머지 노선은 그 아래 한 줄에 하나씩 작고 흐리게 (시간은 오른쪽 끝 정렬). 지하철은 방향별("1호선 소요산행"). 서버 step 메시지 `stop`. 버스는 서울 버스 API 키가 동작해야 나온다 (2026-11-04 현재 401).

**단계 미리보기**: 링 앞/뒤로 단계를 넘기면 "나"는 실제 위치 그대로, 지도만 그 단계 시작점으로 옮긴다 (서버 map-pos `focus`). 실제로 그 단계에 들어서면(앞 단계) 또는 60초 뒤(이전 단계) 원래대로. 실제 위치를 모를 때의 추정 위치(`estimated`)에는 "나"를 그리지 않는다.

**대중교통 후보 고르기**: 카드 한 장에 총 시간(크게) · 환승 · 요금 · 도보, 아래에 구간 시간 비율 막대 (버스 = 채운 막대, 지하철 = 테두리 막대, 도보 = 점선 + "도보 6분"(좁으면 "6분"), 막대 안에 "120번 (5분)" · "경의중앙선 (8분)", 좁으면 시간 생략). 글자는 칸에 맞춰 자른다.

길안내 화면 위 줄 왼쪽에 `1/6 · 14:27 도착` (서버가 준 남은 초 + 받은 시각, 아직 안 탄 버스·지하철은 실시간 첫 도착까지 기다림 포함).
폰 위치를 30초 넘게 못 받으면 왼쪽 아래에 `위치 40초 전` (경로 시작 후 아직 한 번도 없으면 `위치 없음`) → Overland 가 멈췄는지 알 수 있다.
앱을 켜고 서버에 처음 연결되면(그 뒤 6시간마다) 새 버전을 확인해 오른쪽 아래에 `새 버전 0.3.3` 을 띄운다. 설치는 메뉴에서.
`업데이트 확인` → 서버 `GET /app/latest` → 새 버전이면 한 번 더 선택 → 다운로드 · sha256 확인 → 안드로이드 설치 창.
- 처음 한 번은 "이 출처 허용" 설정 화면으로 간다. 허용 후 다시 선택.
- 같은 키로 서명된 APK 만 덮어 설치된다 → 릴리스는 고정 키로: `scripts/release.sh <versionCode> <versionName> [--upload]` (필요한 환경 변수는 스크립트 머리말). 키·토큰은 저장소에 넣지 않는다.
- 디버그 서명 앱에서 넘어갈 때는 한 번 지우고 릴리스 APK 를 설치.

## 네트워크 오류 처리 (0.3.17)
일반 지도 앱처럼 "화면은 비우지 않고, 오래된 정보는 표시하고, 저절로 복구"한다.
| 상황 | 안경 | 서버 |
|---|---|---|
| 안경 ↔ 서버 끊김 | 화면 유지 + 오른쪽 위 `연결 끊김 · 15초`. 2→4→…→30초 (±20%) 재연결, 네트워크가 다시 잡히면 바로. 10초 ping 으로 죽은 연결을 빨리 알아챔 | — |
| 끊긴 동안 링 앞/뒤 | 받아 둔 단계 문구(map-route `steps`)로 혼자 미리보기 (`· 미리보기`), 연결되면 서버 상태로 | — |
| 끊긴 동안 메뉴 요청 (즐겨찾기 안내·경로 다시 찾기·안내 종료·목록) | "연결되면 보냄" → 연결되면 보냄, 30초 지난 것은 버리고 알림 | — |
| 실시간 도착 | 받은 초(`etas`)에서 흐른 시간을 빼 계속 줄여 보여 줌, 1분 넘게 못 받으면 `~4분` | 조회 실패 이유를 보냄 (`실시간 정보 없음 (서버 응답 없음 / API 키 확인 필요)`) |
| 카카오 오류 | — | 타임아웃·연결 실패·5xx 는 0.5초 뒤 1번 더, 400대는 바로 실패 |
| 재탐색 실패 | `재탐색 실패 · 기존 경로 유지` 알림 | 기존 경로 유지, 이탈이 계속되면 30초 뒤 다시 |

**안정성 (0.3.19)**
- 서버 메시지 하나가 잘못돼도 그 메시지만 버림, 그리다 오류가 나도 앱 유지 (둘 다 기록)
- 오류 기록(`CrashLog`, 앱이 죽은 경우 포함, 최근 4KB) → 다음 연결 때 서버로 → Railway 로그 `glass crash report (v…)`
- 지도: 도형을 미터 단위로 한 번만 만들고(도로·경로를 새로 받을 때) 행렬로 옮김. 방향 센서가 있어도 계속 그리지 않고, 1° 넘게 바뀌면 초당 20번까지만 (예전: 초당 60번 + 매번 좌표 재계산)
- 서버: 15초 ping, 응답 없는 연결은 끊음 (죽은 안경을 살아 있다고 보고 목적지 고르기를 기다리지 않게). 메시지·HTTP 처리 오류는 기록만, 놓친 예외는 기록 후 종료 → Railway 재시작(실패 시 5회), 경로는 디스크에서 이어 감. 카카오 사용량 초과(429)는 "카카오 사용량 초과" 로 안내

오류 주입(테스트용): 서버 환경 변수 `FAULTS=kakao,realtime,tiles` (쉼표로). 운영에서는 비워 둔다. 서버 테스트 `src/faults.test.ts`, 안경 `HudStateTest`, 화면 `19_offline`~`22_stop_board_error`.

### 실기 확인할 것 (로컬 검증 필요)
1. 안내 중 안경 Wi-Fi 끄기 → 오른쪽 위 `연결 끊김` 이 뜨고 화면이 그대로인지, 링 앞/뒤로 단계 미리보기가 되는지
2. Wi-Fi 다시 켜기 → 몇 초 안에 다시 연결되는지 (기다림 없이), 미리보기가 실제 단계로 돌아오는지
3. 끊긴 상태에서 메뉴 → 즐겨찾기 장소 선택 → 다시 연결되면 안내가 시작되는지
4. 핫스팟을 끊었다 켜기, 지하철 안처럼 약한 신호에서 재연결 시간
5. 정류장에서 연결을 끊고 1분 이상 → 도착 시간이 줄어들며 `~` 가 붙는지
6. 안내 중 앱 종료 → Wi-Fi 끈 채로 다시 켜기 → `저장된 화면` 으로 마지막 안내가 바로 보이는지

## 방향 (미니맵 회전)
- `TYPE_ROTATION_VECTOR`(지자기 포함)가 있으면 북 기준 방위 → **보고 있는 방향이 위**.
- 없으면 `TYPE_GAME_ROTATION_VECTOR`(상대 각도)로 고개 회전을 따라가고, 경로 위를 걷는 동안 경로 진행 방향으로 0°를 10%씩 보정.
- 둘 다 없으면 경로 진행 방향이 위 (`/viewer` 와 같음).
- Rokid 공식 예제는 GAME_ROTATION_VECTOR 를 쓰고 지자기 유무를 로그로만 확인한다 → 어느 모드가 될지는 실기 로그(`adb logcat -s Heading Route`)로 확인.

## 빌드
```bash
cd glasses-android
echo "sdk.dir=/path/to/android-sdk" > local.properties   # platforms;android-34, build-tools;34.0.0
./gradlew assembleDebug -PDEVICE_TOKEN="$(cat device_token)"  # → app/build/outputs/apk/debug/app-debug.apk
```
서버 주소를 바꾸려면 `./gradlew assembleDebug -PROUTE_SERVER=https://…`.
2026-11-04 클라우드 세션에서 빌드 성공 (3.5MB, 디버그 서명). Maven Central 이 429 를 줄 때는 Google 미러(`maven-central.storage-download.googleapis.com/maven2`)로 바꿔 빌드했다 (세션 전용 init 스크립트, 저장소 설정은 그대로).

디버그 키는 빌드 환경마다 달라서, 다른 곳에서 빌드한 APK 로 덮어 설치하면 서명 불일치로 실패할 수 있다 → 기존 앱을 지우고 설치.
